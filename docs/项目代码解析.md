## 一、项目规模与结构

| 维度 | 数量 |
| --- | --- |
| 后端 Java 文件 | 64 个，约 2150 行 |
| 前端 Vue/JS 文件 | 31 个，约 9300 行（含样式） |
| 数据表 | 10 张 |
| REST 端点 | 42 个（38 个路径） |
| 自动化用例 | 接口 56 个 + 页面 10 个 + 流程 6 步 |

后端按业务垂直分包，每个包内部再分层：

```
com.noteworkshop
├─ common       Result / PageResult / BizException / GlobalExceptionHandler
├─ config       MyBatisPlusConfig / WebMvcConfig / OpenApiConfig / DataInitializer / SpaForwardController
├─ security     JwtUtil / AuthInterceptor / AdminInterceptor / UserContext
├─ user         注册登录、资料、头像
├─ note         笔记 CRUD、公开流、点赞、详情
├─ comment      评论树、级联删除
├─ follow       关注、粉丝、热门作者
├─ admin        用户管理、审核、下架、评论管理、AI 统计
├─ ai           阅读辅助、客服会话、调用日志
└─ file         本地文件上传
```

**为什么垂直分包而不是 controller/service/mapper 三大包？**
业务边界清晰，一个功能改动只落在一个包里；答辩时也更容易"按模块讲"。

## 二、数据库设计（10 张表）

| 表 | 作用 | 关键设计 |
| --- | --- | --- |
| `user` | 用户 | `username` 唯一；`password` 存 BCrypt；`role` 区分 USER/ADMIN；`status` 控制禁用 |
| `note` | 笔记 | `is_public` + `status` 双字段；冗余 `like_count`、`comment_count`；`reject_reason`、`reviewed_at` |
| `note_image` | 笔记配图 | 一对多，`sort` 控制顺序 |
| `note_like` | 点赞 | **唯一索引 (user_id, note_id)** 保证幂等 |
| `comment` | 评论 | `parent_id` 自关联；`deleted` 逻辑删除 |
| `follow` | 关注 | 唯一索引 (follower_id, followee_id) 防重复关注 |
| `note_ai` | AI 结果 | **唯一索引 note_id**：一篇笔记只保留一条 AI 辅助结果 |
| `ai_call_log` | AI 调用日志 | `scene`、`success`、`latency_ms`、`error_msg`，用于后台统计 |
| `ai_chat_session` | 客服会话 | 归属 `user_id`，做会话隔离 |
| `ai_chat_message` | 会话消息 | `role` 区分 user/assistant，按 id 递增排序 |

**设计要点**

1. `is_public` 与 `status` 分离：前者是用户意愿，后者是平台审核结果，二者组合才能决定"是否对外可见"。
2. 计数冗余（`like_count`/`comment_count`）：列表页排序和展示避免 `count(*)`，用 SQL 原子自增减。
3. 逻辑删除只用于评论（`deleted`），笔记用物理删除 + 级联清理关联表。
4. 索引：`(is_public, status, like_count)` 服务公开流与最热排序；`(user_id, deleted)` 服务评论查询。

对应的建表脚本：`sql/schema.sql`，升级脚本：`sql/upgrade_v2.sql`。

## 三、一次请求的完整链路

以"发表评论"为例（`POST /api/notes/{id}/comments`）：

```
浏览器 axios
  → vue.config.js 代理 /api → 127.0.0.1:8080
  → Tomcat / DispatcherServlet
  → AuthInterceptor.preHandle（解析 Bearer token，写入 UserContext）
  → CommentController.add（@Valid 校验 body）
  → CommentService.add
       ├─ 校验笔记存在且公开且 status=1
       ├─ 校验 parentId 属于同一篇笔记
       ├─ insert comment
       └─ update note set comment_count = comment_count + 1
  → Result.ok(CommentVO)
  → 全局异常处理器（成功时不介入）
  → JSON {code:0,message:"ok",data:{...}}
  → axios 响应拦截器解包 data
```

前端拦截器：`frontend/src/api/index.js:23`（请求加 token）、`:35`（响应解包、401 跳登录）。
后端拦截器注册：`config/WebMvcConfig.java:30`，顺序为 Auth(1) → Admin(2)。

## 四、八个核心机制

### 1. JWT 认证链路

| 环节 | 代码 | 说明 |
| --- | --- | --- |
| 签发 | `security/JwtUtil.java:25` | `subject=userId`，claim 带 username，7 天过期 |
| 算法 | `JwtUtil.java:23` | `Keys.hmacShaKeyFor(secret)`，密钥 51 字节 → jjwt 选择 **HS384** |
| 解析 | `JwtUtil.java:36` | `parser().verifyWith(key)` 验签 + 过期校验 |
| 拦截 | `security/AuthInterceptor.java:17` | 取 `Authorization: Bearer x`，失败抛 401 业务异常 |
| 上下文 | `UserContext`（ThreadLocal） | 请求线程内取当前用户，`afterCompletion` 必须 `clear()` 防线程池串号 |
| 放行 | `AuthInterceptor.java:19` | OPTIONS 预检直接放行，避免 CORS 预检被拦成 500 |

**答辩要点**：JWT 无状态、可水平扩展；代价是无法主动失效（本项目退出登录只是前端删 token），生产可加 Redis 黑名单或短 token + refresh token。

### 2. 审核状态机（项目最容易被追问的业务）

状态定义在 `note/NoteService.java:24-27`：

```
1 已发布   2 待审核   3 已驳回   0 已下架
```

流转规则（`NoteService.java:42` 创建、`:59` 修改）：

| 动作 | 条件 | 结果状态 |
| --- | --- | --- |
| 创建私有笔记 | `is_public=0` | 1（直接可见，仅自己） |
| 创建公开笔记 | `is_public=1` | 2（待审核） |
| 修改任何笔记 | 公开 | 2（重新审核，清空驳回原因） |
| 修改任何笔记 | 私有 | 1 |
| 管理员通过 | 当前=2 | 1，写 `reviewed_at` |
| 管理员驳回 | 当前=2 | 3，写 `reject_reason` |
| 管理员下架 | 任意 | 0 |

公开列表/详情的可见条件（`NoteService.java:90-101`、`:116`）：
`is_public=1 AND status=1`；作者本人可看自己的全部状态。
这就是"前端传了 is_public 也不能立刻公开"的原因——**服务端强制覆盖 status**。

### 3. 点赞：幂等 + 计数

`NoteService.java:145`：

1. 校验笔记必须公开且已发布（`:150`）。
2. `selectCount` 判断是否已点赞。
3. 已赞 → 删记录 + `like_count = GREATEST(like_count-1, 0)`；未赞 → 插入 + `+1`。
4. 返回最新点赞数与状态。

**唯一索引兜底**：`note_like` 上的 `(user_id, note_id)` 唯一键，即使并发重复插入也只会成功一条。
**追问准备**：高并发下"先查后插"仍有竞态，可改为 `INSERT ... ON DUPLICATE KEY` 或 Redis 计数 + 异步落库。

### 4. 评论树与级联删除

- 查询：`CommentService.java:36` 一次查出该笔记全部未删除评论，内存里 `groupingBy(parentId)` 组装两级树（避免递归查库）。
- 新增：`:70` 校验父评论属于同一笔记，插入后 `comment_count+1`。
- 删除：`:103` 本人删除、`:115` 管理员删除，核心是 `:125 removeCascade`：
  1. 查出该笔记所有未删除评论；
  2. 按 parentId 建邻接表；
  3. BFS 从根评论向下收集所有子孙 id；
  4. 批量 `UPDATE comment SET deleted=1 WHERE id IN (...)`；
  5. `comment_count` 减去删除条数（`GREATEST(...,0)` 防止负数）。

**为什么用逻辑删除**：保留审计痕迹，且回复关系不会断链；查询统一带 `deleted=0`。

### 5. 关注与热门作者

- 关注/取关：`FollowService.follow/unfollow`，唯一索引防重复；不能关注自己。
- 粉丝数：`count(*) where followee_id=?`。
- 热门作者：`GROUP BY followee_id ORDER BY count(*) DESC LIMIT 10`，再批量查用户信息（避免 N+1）。
- 作者主页：`profile` 返回粉丝数、公开笔记数、当前用户是否已关注。

### 6. 管理后台与权限

- `AdminInterceptor`（`security/AdminInterceptor.java`）在 Auth 之后执行，查库校验 `role == ADMIN`，否则 403。
- 注册顺序在 `WebMvcConfig.java:41`：`/api/admin/**` 上叠加两个拦截器。
- 管理能力：`AdminService.java:43` 概览、`:62` 用户列表、`:73` 禁用、`:86` 笔记筛选、`:98` 审核、`:114` 下架、`:124` 删评论、`:128` AI 统计。
- 细节：不能禁用管理员账号（`:75`）；审核只接受"待审核"状态（`:99`），防止重复审核 / 越权改状态。

### 7. AI 阅读辅助

`AiService.java:59 generate`：

1. 校验笔记归属（`NoteService.requireOwned`）。
2. 按类型拼 prompt（`:208`）：SUMMARY 200 字总结 / AUDIENCE 3 类人群 / SCORE 三维打分。
3. `ChatClient.prompt().system(...).user(...).call().content()`（`:200`）。
4. 成功/失败都写 `ai_call_log`（`:239`），失败抛 503 并带上简要原因。
5. 结果**不落笔记**，用户点"保存"才调用 `:80 save`，写 `note_ai`（唯一索引保证一篇一条）。

### 8. AI 客服：会话隔离 + 滑动窗口

`AiService.java:115 chat`：

1. `sessionId` 为空则新建会话（标题取首条消息前 20 字），否则 `requireSession` 校验归属（`:189`，越权 403）。
2. 取最近 `windowSize=20` 条消息（`:127`），反转成时间正序。
3. 先落用户消息，再拼 prompt（`:219` 把历史格式化成"用户：/助手："），调用模型。
4. 成功落助手消息，更新会话时间；失败落日志并抛 503。
5. **方法故意不加 `@Transactional`**：AI 失败时用户消息和调用日志要保留，供统计与排障。

**追问准备**：为什么只带 10 轮？控制 token 成本与延迟；更优做法是摘要压缩历史 + 向量检索。

## 五、前端架构

```
src/
├─ api/index.js        axios 实例、请求/响应拦截器、401 跳转
├─ store/auth.js       reactive 全局登录态 + localStorage 持久化
├─ store/toast.js      全局提示
├─ router/index.js     history 路由 + 守卫（requiresAuth / admin / guestOnly）
├─ views/              11 个页面（首页、详情、编辑器、我的、资料、作者、AI、后台、登录、注册、404）
└─ components/         NavBar、NoteCard、Pagination、CommentTree、ToastHost 等
```

关键点：

- **路由守卫**（`frontend/src/router/index.js:89`）：未登录访问受保护页 → 跳登录；`admin` 页面额外校验角色。
- **axios 拦截器**：请求自动加 `Bearer`；响应统一解包 `data`；`code=401` 清 token 并跳登录。
- **开发代理**：`vue.config.js` 把 `/api`、`/uploads` 代理到 8080，开发时无跨域。
- **生产托管**：`npm run build` 产物复制到后端 `static/`，由 `SpaForwardController` 做 history 路由回退（`/notes/1` 刷新不 404）。

## 七、设计取舍与已知不足（答辩时主动说，反而加分）

| 点 | 现状 | 更好的做法 |
| --- | --- | --- |
| 点赞计数 | 先查后改 + SQL 自增 | 高并发用 `INSERT ... ON DUPLICATE KEY` / Redis 计数 |
| JWT 注销 | 无服务端黑名单 | Redis 存 jti 黑名单 + refresh token |
| 热门作者 | 每次实时 `GROUP BY` | 定时任务算榜 + 缓存 |
| 评论树 | 一次查全量内存组装 | 深分页/海量评论改为路径枚举或闭包表 |
| 文件存储 | 本地磁盘 | OSS/S3 + CDN，数据库只存 key |
| AI 调用 | 同步、无流式 | SSE 流式输出 + 超时/重试/限流 |
| 安全 | 有 BCrypt、参数校验、权限拦截 | 加接口限流、验证码、敏感词、操作审计表 |
| 测试 | 集成脚本为主 | 补 Service 层单元测试（JUnit + Mockito） |
| 密钥 | yml 有开发默认值 | 全部走环境变量/配置中心 |
