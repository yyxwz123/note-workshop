## Day 1 · 跑通项目，建立全局观

### 上午（2.5h）：把项目跑起来，当一次真实用户

**目标**：知道每个页面背后调了哪个接口。

1. 启动三件套：
   ```powershell
   start-mysql
   cd note-workshop && mvn spring-boot:run
   cd frontend && npm run serve
   ```
2. 用 `demo01 / 123456` 完整走一遍：
   注册 → 登录 → 发布公开笔记 → 退出 → `admin / admin123` 审核通过 → 点赞 → 评论+回复 → 关注作者 → 打开 AI 助手 → 管理后台看统计。
3. 打开浏览器 DevTools → Network，记录 5 个请求的「方法 + 路径 + 请求体 + 响应」，填成表格。

**产出**：一张「用户动作 → 接口」对照表（至少 8 行）。

### 下午（3h）：分层与请求链路

**读代码**（按顺序，只看主流程）：

- `common/Result.java`、`PageResult.java`
- `note/NoteController.java` → `note/NoteService.java`
- `config/WebMvcConfig.java`（拦截器注册顺序）

**动手**：手绘「发表评论」的完整链路：

```
浏览器 → 代理 → 拦截器 → Controller → Service → Mapper → MySQL → 响应
```

在图上标出：参数校验发生在哪、权限判断发生在哪、事务边界在哪。

**产出**：一张手绘链路图（拍下来存手机，答辩前再看）。

### 晚上（2h）：数据库设计

1. 读 `sql/schema.sql`，画出 10 张表的 ER 图（重点：note、comment、note_like、follow、note_ai）。
2. 找出 5 个索引，写下"为什么建这个索引、服务哪条 SQL"。
3. 口述练习（录音 3 分钟）：「这个项目解决什么问题？后端怎么分层？为什么这么分？」

**验收**：合上代码，白纸画出模块图 + ER 图，标注 3 个核心接口。

## Day 2 · 认证鉴权与笔记主流程

### 上午（2.5h）：JWT 全链路

**读代码**：`security/JwtUtil.java`、`AuthInterceptor.java`、`UserContext.java`、`config/WebMvcConfig.java`

**必须弄懂**：

- JWT 三段结构（header.payload.signature），本项目用 **HS384**（密钥长度决定）
- token 里放了什么（userId、username、iat、exp），**不放密码**
- 拦截器如何取 token、验签、放行 OPTIONS
- ThreadLocal 为什么必须在 `afterCompletion` 清理（线程池复用会串用户）

**动手**：

1. 用 curl 登录拿 token，手动调 `/api/users/me`：
   ```bash
   curl -X POST localhost:8080/api/auth/login -H "Content-Type: application/json" -d "{\"username\":\"demo01\",\"password\":\"123456\"}"
   curl localhost:8080/api/users/me -H "Authorization: Bearer <token>"
   ```
2. 改掉 token 最后一个字符，观察 401；
3. 不带 token 访问，观察 401；
4. 普通用户 token 访问 `/api/admin/dashboard`，观察 403。

**产出**：一张「401 vs 403」对比说明。

### 下午（3h）：用户、文件上传、笔记 CRUD 与审核

**读代码**：`user/UserService.java`、`file/FileStorageService.java`、`note/NoteService.java:42-116`

**必须弄懂**：

- BCrypt 为什么不可逆、盐存在哪
- 文件上传四道校验：非空、后缀白名单、大小限制、UUID 重命名
- 笔记为什么必须绑定书名；私有/公开与 status 的关系

**动手（关键）**：走一遍审核闭环，每步用 SQL 看状态：

```sql
SELECT id,title,is_public,status,reject_reason FROM note ORDER BY id DESC LIMIT 3;
```

发布公开 → status=2 → 后台驳回（填原因）→ status=3 → 用户修改 → status=2 → 通过 → status=1。

**产出**：状态流转表（动作 → 条件 → 新状态 → 可见性）。

### 晚上（2h）：状态机与 SQL 巩固

1. 默写状态机（1/2/3/0 各代表什么、谁能改）。
2. 写 6 条 SQL：查公开流、查待审核、查我的笔记、查热门、查某作者公开笔记、查我点赞的。
3. 口述录音：「为什么公开笔记不能立刻可见？服务端在哪里强制覆盖了 status？」

**验收**：能解释"前端传 is_public=1 但没通过审核为什么看不到"。

## Day 3 · 社区互动与管理后台（最容易被追问的一天）

### 上午（3h）：点赞并发 + 评论树

**读代码**：`note/NoteService.java:145-178`、`comment/CommentService.java:36-150`

**必须弄懂**：

- 点赞幂等的两层保障：唯一索引 + 先查后改
- 计数为什么用 `like_count = like_count + 1` 而不是"查出来再写回"
- 评论树为什么一次查全量再内存组装（避免 N+1）
- 级联删除为什么用 BFS 收集子孙 id，再一条 `UPDATE ... IN` 批量逻辑删除

**动手**：

1. 写一个 20 次并发点赞的小脚本（Node/PowerShell 均可），观察 `like_count` 是否准确，记录现象；
2. 手动删一条有回复的评论，验证子回复同时消失，`comment_count` 正确减少。

**产出**：级联删除伪代码（不看代码手写）+ 并发测试结论。

### 下午（3h）：关注、粉丝、热门作者、管理后台

**读代码**：`follow/FollowService.java`、`admin/AdminService.java`、`security/AdminInterceptor.java`

**必须弄懂**：

- 关注表唯一索引防重复；不能关注自己
- 粉丝数统计、热门作者 `GROUP BY ... ORDER BY count DESC`
- 管理后台为什么要第二个拦截器，为什么在 Auth 之后
- 审核接口为什么校验"当前必须是待审核"（防重复审核/越权）
- 为什么不能禁用管理员账号

**动手**：用 `admin` 走一遍用户禁用/启用、笔记下架、删除违规评论；再用普通账号访问 `/api/admin/**` 验证 403。

**产出**：管理后台功能清单（8 个接口 + 各自权限）。

### 晚上（2h）：白板训练

1. 不看代码写出 `removeCascade` 的 BFS 逻辑（10 行以内）。
2. 解释 3 个索引分别服务哪条 SQL。
3. 口述录音：「点赞数出现不一致，你怎么排查和修复？」

**验收**：白板 5 分钟讲清"评论树 + 级联删除"。

## Day 4 · AI 模块、前端架构与测试

### 上午（3h）：AI 阅读 + 客服

**读代码**：`ai/AiService.java:59-165`、`ai/AiController.java`

**必须弄懂**：

- Spring AI 的 ChatClient 怎么调 OpenAI 兼容接口（DeepSeek）
- 三种 prompt 的差异（总结/人群/评分）
- 为什么 AI 结果不直接写笔记，要用户手动保存（`note_ai` 唯一索引）
- 客服会话隔离：`requireSession` 越权 403
- 滑动窗口：只取最近 20 条，控制 token 成本
- 失败路径：写 `ai_call_log` → 抛 503 → 前端提示

**动手**：

1. 不配 Key 调 AI 接口，观察 503 与前端提示；
2. 查 `ai_call_log` 看失败记录（scene/success/latency）；
3. 配一个真实 Key（可选），走通一次总结并保存到笔记。

**产出**：AI 请求链路图（含成功/失败两条路径）。

### 下午（3h）：前端架构与联调

**读代码**：`frontend/src/api/index.js`、`router/index.js`、`store/auth.js`、`vue.config.js`

**必须弄懂**：

- axios 拦截器：请求加 token、响应解包、401 跳登录
- 路由守卫：requiresAuth / admin / guestOnly
- 开发代理怎么解决跨域；生产为什么由后端托管
- history 路由刷新 404 怎么解决（`SpaForwardController`）

**动手**：

1. 改一个页面文案，验证热更新；
2. 停掉后端，点登录，看错误提示是否友好；
3. 用未登录状态访问 `/me`，验证跳转登录。

**产出**：一张前后端协作图（8081 开发 / 8080 生产）。

### 晚上（2h）：测试与质量

1. 跑三个脚本：`node scripts/api-test.mjs`、`ui-check.mjs`、`ui-flow.mjs`，读报告。
2. 打开 `docs/api-test-report.md`，找出 3 个失败会暴露的 bug（例如：待审核泄露到公开列表）。
3. 自己加一个接口用例（如"私有笔记详情对他人 404"），跑通。

**验收**：讲清 56 个用例覆盖了哪些风险点。

## Day 5 · 全流程演练与模拟答辩

### 上午（2.5h）：Demo 脚本与应急

**5 分钟 demo 顺序**（背下来）：

1. 首页：公开笔记流 + 热门作者（10 秒）
2. 登录 demo01 → 发布一篇公开笔记 → 提示"待审核"（40 秒）
3. 退出，登录 admin → 管理后台审核通过（40 秒）
4. 回前台：点赞、评论、回复、关注作者（60 秒）
5. AI 助手：生成总结 → 保存到笔记（40 秒）
6. 个人主页 / 作者主页 / 我的笔记状态标签（30 秒）
7. 收尾：说一句架构总结（20 秒）

**应急预案**：

| 故障 | 处理 |
| --- | --- |
| MySQL 没启动 | `start-mysql`，等 3 秒 |
| 8080 被占用 | `netstat -ano | findstr :8080`，结束进程或用 8081 |
| 页面空白 | 硬刷新 `Ctrl+F5`；确认后端在跑 |
| 演示数据被清空 | 现场注册 + 发一篇，或提前备份 SQL |
| AI 报 503 | 坦然说明"未配置 Key，已做优雅降级"，展示日志与统计 |
| 网络断 | 全本地，不依赖外网（AI 除外） |

### 下午（3h）：题库自测

打开 [答辩题库](答辩题库.md)，按分类刷：

1. 第一遍：口述作答，答不上的标记；
2. 第二遍：只看标记题，写出关键词；
3. 第三遍：随机抽 10 题，限时 1 分钟/题。

**目标**：40 题至少答对 32 题。

### 晚上（2h）：模拟答辩

1. 自我介绍 1 分钟 + 项目介绍 3 分钟（录音）；
2. 让同学/自己随机抽 10 个问题追问；
3. 回放录音，记录 3 个卡壳点，当晚补齐；
4. 准备结尾三句话：**亮点、不足、下一步**。

**验收**：完整走一遍不超时、不冷场。
