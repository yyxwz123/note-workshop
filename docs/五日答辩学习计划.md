> 目标：5 天后能独立讲清项目、现场演示不翻车、回答追问有依据。

> 侦察数据：131 个代码文件 / 15068 行 · 42 个接口 · 10 张表 · 2 个测试脚本。

## Day 1 · 跑通项目，建立全局观

**目标**：说清"项目做什么、怎么分层、数据从哪来"。

### 上午（2h）— 当一次真实用户

- **读**：`README.md`、[代码解析](项目代码解析.md) 第一、二节
- **懂**：三类账号、6 个主要页面、页面数据来自哪个接口
- **做**：
  ```powershell
  start-mysql
  cd note-workshop && mvn spring-boot:run
  cd frontend && npm run serve
  ```
  走完：注册 → 登录 → 发公开笔记 → 退出 → admin 审核 → 点赞 → 评论+回复 → 关注 → AI → 后台。
- **产**：用户动作 → 接口对照表（≥8 行）
- **验**：不看代码说出 6 个页面各自调用哪个接口

### 下午（2h）— 分层与请求链路

- **读**：`common/Result.java`、`note/NoteController.java`、`note/NoteService.java:42-116`、`config/WebMvcConfig.java:30-60`
- **懂**：Controller 只做校验与组装；Service 管业务/权限/事务；Mapper 只管 SQL；拦截器先 Auth 后 Admin
- **做**：在"发表评论"链路上标出 5 个检查点（鉴权、参数校验、归属校验、事务、异常兜底）
- **产**：手绘链路图
- **验**：合上代码画出链路，并说出每层职责

### 晚上（1h）— 数据模型 + 口述

- **读**：`sql/schema.sql`
- **做**：画 10 张表 ER 图；录音 3 分钟"这个项目是什么、怎么分层"
- **产**：ER 图 + 录音
- **验**：白纸默写表名与三条核心关系

**可能被问**：介绍一下项目 / 为什么这样分层 / 为什么这些表

## Day 2 · 认证鉴权与笔记主流程

**目标**：讲清一次请求如何被认证，以及公开笔记为什么必须审核。

### 上午（2h）— JWT 全链路

- **读**：`security/JwtUtil.java:25-44`、`security/AuthInterceptor.java:17-37`、`security/UserContext.java`、`config/WebMvcConfig.java:30-44`
- **懂**：HS384 如何选算法、payload 放什么、ThreadLocal 为什么必须清理、OPTIONS 预检为什么放行
- **做**（4 组实验）：
  ```bash
  curl -X POST localhost:8080/api/auth/login -H "Content-Type: application/json" -d "{\"username\":\"demo01\",\"password\":\"123456\"}"
  curl localhost:8080/api/users/me -H "Authorization: Bearer <token>"
  curl localhost:8080/api/users/me -H "Authorization: Bearer <改坏一个字符的token>"
  curl localhost:8080/api/admin/dashboard -H "Authorization: Bearer <普通用户token>"
  ```
- **产**：401 vs 403 对照表
- **验**：说出一次鉴权经过的类与顺序

### 下午（2h）— 笔记与审核状态机

- **读**：`note/NoteService.java:24-27,42-73,116-142`、`admin/AdminService.java:98-122`
- **懂**：1/2/3/0 含义；公开创建/修改一律回 2；服务端强制覆盖 status；驳回原因与重提
- **做**：走一遍"发布 → 驳回 → 修改 → 通过"，每步执行：
  ```sql
  SELECT id,title,is_public,status,reject_reason FROM note ORDER BY id DESC LIMIT 1;
  ```
- **产**：状态流转表（动作 / 条件 / 新状态 / 可见性）
- **验**：说出每个动作后的 status 与"谁能看到"

### 晚上（1h）— 默写与口述

- **做**：默写状态机；录音"前端传 is_public=1 为什么不能立刻公开"
- **产**：状态机卡片（贴显示器）
- **验**：30 秒内答完

**可能被问**：JWT 能注销吗 / 401 和 403 区别 / 用户能不能绕过审核

## Day 3 · 互动功能与管理后台（最容易被追问）

**目标**：讲清点赞并发、评论级联、关注统计与后台权限。

### 上午（2h）— 点赞与评论

- **读**：`note/NoteService.java:145-178`、`comment/CommentService.java:36-58,125-150`
- **懂**：唯一索引 + 原子计数如何保证幂等；一次查询建树避免 N+1；BFS 收集子孙再批量逻辑删除
- **做**：并发点赞 20 次观察 `like_count`；删除一条有回复的评论，验证子回复消失且计数正确
- **产**：级联删除伪代码（不看代码手写）+ 并发测试结论
- **验**：白板 5 分钟讲清"树怎么建、怎么删"

### 下午（2h）— 关注、粉丝与后台

- **读**：`follow/FollowService.java`、`admin/AdminService.java:43-128`、`security/AdminInterceptor.java`
- **懂**：唯一索引防重复关注；`GROUP BY` 排行；双拦截器顺序；审核只接受待审核；不能禁用管理员
- **做**：关注/取关并核对粉丝数；admin 禁用用户、下架笔记；普通用户访问 `/api/admin/**` 验证 403
- **产**：管理后台 8 个接口的权限与状态校验表
- **验**：说清每个管理接口"谁能调、什么状态能调"

### 晚上（1h）— 间隔复习 + 口述

- **做**：回看 Day 1 架构图并补全；录音"点赞数不一致怎么排查"
- **产**：录音 + 补全图
- **验**：能说出"定位 → 修复 → 预防"三步

**可能被问**：并发点赞会不会重复 / 为什么不用外键级联 / 索引服务哪条 SQL / 管理员越权怎么防

## Day 4 · AI 模块、前端与测试

**目标**：讲清 AI 的成功与失败两条路径，以及前后端如何协作。

### 上午（2h）— AI 阅读与客服

- **读**：`ai/AiService.java:59-110,115-165,189-200,239-250`、`ai/AiController.java`
- **懂**：三类 prompt；结果必须手动保存且一篇一条；会话归属校验；最近 20 条窗口；失败写日志并降级 503
- **做**：无 Key 调 `generate` 与 `chat` 看 503；查 `ai_call_log`；打开后台 AI 统计
- **产**：AI 成功/失败双路径图
- **验**：说清失败时用户消息、日志、响应分别去了哪

### 下午（2h）— 前端与联调

- **读**：`frontend/src/api/index.js:23-62`、`frontend/src/router/index.js:89-100`、`frontend/vue.config.js`
- **懂**：axios 解包与 401 跳转；路由守卫三类 meta；代理；打包后 SPA 回退
- **做**：改页面文案看热更新；停后端点登录看提示；跑 `node scripts/api-test.mjs`
- **产**：前后端协作图（8081 开发 / 8080 生产）+ 测试结论
- **验**：说清两种运行方式的差异与各自用途

### 晚上（1h）— 口述与弱项

- **做**：复述 AI 链路；列出 3 个弱项并各配一句改进方案
- **产**：弱项清单（答辩时主动说）
- **验**：每个弱项能在 30 秒内讲完"现状 + 改进"

**可能被问**：AI 成本怎么控 / 没有 Key 怎么演示 / 跨域怎么解决 / 为什么打包后刷新不 404

## 六、应急预案

| 故障 | 处理 |
| --- | --- |
| MySQL 未启动 | `start-mysql`，等 3 秒 |
| 8080 被占用 | `netstat -ano \| findstr :8080` 结束进程，或改用 8081 |
| 页面空白 | `Ctrl+F5`；确认后端在跑；看控制台报错 |
| 数据被清空 | 现场注册 + 发一篇；或提前备份 SQL |
| AI 报 503 | 说明未配 Key、已做降级，展示 `ai_call_log` 与后台统计 |
| 网络断 | 系统全本地，不依赖外网（AI 除外） |
